> 本文档记录启航AI工作台（qihang-ai-desktop）的每一次更新，**新条目永远加在最上方的「未发布」区**。
>
> - 历史条目（2026-07-08 ~ 2026-09-27，共 166 次提交）由 git 提交记录回填，按日期分组，保留 commit 短哈希便于追溯：`git show <hash>`。
> - 发布时把「未发布」内容归入新的版本小节，并同步 `package.json` 的 `version`。

## 记录约定

- 条目前缀类型：`feat` 新增 / `fix` 修复 / `refactor` 重构 / `perf` 优化 / `chore` 杂项与依赖 / `docs` 文档 / `build` 打包发布
- 一条只写一件事，写清「改了什么」和「为什么」，不写「优化」这类无信息量的表述
- 影响用户可见行为的改动（UI、配置项、IPC、依赖版本）必须入日志；纯过程性提交可不入
- 日期以提交日期为准；同一批改动合并为一个条目，不按 commit 逐条罗列

## 未发布

### 2026-10-04 · 移除 opencode 引擎 + pi agent 升级 1.0.2

**移除 opencode**

- `refactor` 删除 opencode 全部代码：`electron/services/opencode-agent.ts`、`opencode-process.ts`、`opencode-config.ts`、`agent-runtime.ts`（共 652 行），并移除依赖 `@opencode-ai/sdk@1.18.32`。**原因**：工作台的 20+ 工具全是办公域（笔记库/数据集/任务/提醒/知识库/联网搜索），无 edit/bash/git，pi 与 opencode 的 coding agent 能力用不上，只是当 LLM + 工具循环跑；双引擎等于双份事件流适配 + 模型映射 + 配置同步 + 子进程托管，维护成本翻倍，且没有任何多 agent 场景（子代理并行、角色分工）需要它。
- `fix` 修复默认运行时反而丢工具的问题：原逻辑「检测到 opencode 即默认 opencode」，而 opencode 分支显式丢弃 customTools（等 MCP 化），导致默认路径下 AI 拿不到全部本地工具。移除后对话、飞书派活/追问、定时日报、AI 工具箱统一走 pi，工具面完全一致。
- `chore` 移除引擎切换 UI 与接口：`chat:send` 去掉运行时分流、`agent:runtime:get/set` 两个 IPC 与 preload/env.d.ts 声明、ChatView / PlannerView / TaskDetailView 的引擎下拉及相关状态与样式；模型记忆键沿用 `chat_home_model_pi`，用户已选模型不丢。
- `fix` 顺带修复任务追问的模型选择失效：`task:followup` 去掉 runtime 参数，并把所选模型真正接到 pi 的 `modelPattern`（此前 pi 分支忽略该参数）。
- `build` 安装包瘦身：不再捆绑 opencode 二进制（原约 +180MB）；electron-builder 排除规则从 `pi-coding-agent/node_modules/**` 改到顶层 `node_modules/**`（pi 1.0 依赖被提升），剔除 `@google/genai`、`@anthropic-ai/sdk`、`@aws-sdk/*`、`@smithy/*` 等用不到的云厂商 SDK，约再省 30MB+。
- `docs` README 与《功能设计与使用说明》全面改为单引擎 pi 表述，含架构图、设计原则、里程碑与「去掉双引擎后的收益」对照表。

**pi agent 1.0.2 升级**

- `chore` `@earendil-works/pi-coding-agent` 0.80.3 → 1.0.2。破坏性变更集中在模型层：`AuthStorage`、`ModelRegistry.create()` 已从包导出移除。
- `refactor` `pi-agent.ts` 迁移到新 API：`await ModelRuntime.create({ authPath, modelsPath })` 作为权威模型/凭据运行时，`new ModelRegistry(runtime)` 作为同步只读门面（`find` / `getAll` / `getAvailable` / `getProviderDisplayName` / `hasConfiguredAuth` 语义不变）；`createAgentSession` 的 `authStorage` + `modelRegistry` 两参合并为 `modelRuntime`。
- `fix` 适配 `registry.refresh()` 变为异步（1.0 内部重新读取 models.json），模型配置热重载链路改为 `await`，保证「设置里改完模型立即生效」。
- 说明：事件语义（`message_update` / `tool_execution_start|end`）、`PromptOptions`、`SessionManager.open`、`SettingsManager.create`、`DefaultResourceLoader` 在 1.0 均未变化，因此工具层与 UI 零改动。会话文件仍为 `~/.pi/agent/sessions/assistant-v2-<id>.jsonl`，历史会话可继续使用。
- 验证：`npm run compile:electron`、`npm run build` 通过；`vue-tsc` 错误数与改动前基线一致（66 个，均为既有的 `env.d.ts` 全局声明失效问题）；另做 pi 1.0 冒烟验证 ModelRuntime/ModelRegistry/自定义工具调用/流式事件/refresh 全部正常。
