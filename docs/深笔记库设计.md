>

> - 第 2 节「先接线后造新」的检索思路（把 BM25/hybrid 接上）不再适用于 AI 侧检索。
>
> 仍然成立的部分：Markdown 文件是唯一真相、数据库索引是可丢弃派生物、
> `rag.ts` 的 BM25/hybrid 至今无调用方（索引死路径待清理）。

> 对应新定位「基于本地笔记库为主体，构建个人 AI 工作台」（见 [README.md](../README.md)）。
> 本文档基于 2026-10 对现有代码的实测盘点，规划笔记库从"只读浏览器"到"笔记主体"的演进路径。

## 1. 现状盘点（实测，含代码位置）

| 能力 | 现状 | 位置 |
|------|------|------|
| 浏览 | 左侧文件树 + 右侧 Markdown 预览，多库下拉切换 | `src/views/NotesView.vue` |

## 2. 设计原则

1. **Markdown 文件是唯一真相**：磁盘上的 `.md` 文件永远可以直接用任何编辑器打开、随时带走；数据库（索引、链接表）只是可丢弃、可重建的派生物。
2. **改文件不改模型**：所有笔记文件改动（编辑器、AI、用户外部编辑）最终都是普通文件写入；fs.watch + 索引自动跟随，单一同步路径。
3. **先接线后造新**：把已写好但断线的 BM25/hybrid 检索先接上，这是性价比最高的一步。
4. **结构层用约定不造格式**：标签、双链全部用社区通用约定（YAML frontmatter、`[[wiki链接]]`），不发明私有格式。

---

## 3. 分期设计

### 一期：打通检索（最高性价比，改动小收益大）

**目标：让"已有的好东西"跑起来。**

1. **UI 搜索走索引**：`kb:search`（main.ts）从暴力扫描改为调 `rag.keywordSearch`（BM25），带标题/路径/正文摘要高亮返回。
2. **AI 获得搜索工具**：`tools.ts` 新增 `search_notes(query, projectId?)` —— BM25 返回 top-N 文件+分数+匹配摘要，AI 不再靠 `list_notes` 遍历猜。
3. **chunk 上下文增强**：`kb_chunks` 入库时在块首拼上 `标题 / 相对路径`（indexer.ts:34-41），检索召回后能报出来源；index-worker.ts 的 title 统一用 `extractTitle`。
4. **hybrid 检索灰度**：配置开关（默认关）。开启后 `search_notes` 与 `kb:search` 走 `rag.hybridSearch`（向量+关键词融合），消费已建好的 embedding——把死代码变活。

**验收**：UI 搜索不再扫目录；对话里问"我之前记过 X 的笔记吗"AI 能一次定位到文件。

### 二期：编辑体验（从查看器到编辑器）

**目标：不离开工作台就能完成笔记的闭环。**

1. **编辑模式**：NotesView 右侧加"编辑/预览"切换（Markdown 源码编辑 + 现有 marked 预览；编辑器用 `textarea` 起步，后续可换 CodeMirror）。
2. **保存安全**：写入走主进程统一入口（safeNotePath 防越权 + mtime 乐观锁——打开时的 mtime 与写回时不一致则提示冲突，避免覆盖外部修改）。
3. **文件管理**：新建（自动命名 `未命名-时间戳.md`）、重命名、删除（移入 `.trash/` 而非真删，可恢复）、在树内移动。
4. **自动重索引**：编辑保存后 fs.watch 已有的 10s 防抖重跑索引即可，无需额外机制。

**验收**：在应用内新建一篇笔记、编辑、搜索能立刻找到、AI 也能读到。

### 三期：结构层（标签、双链、frontmatter）

**目标：笔记从"一堆文件"变成"知识网络"。**

1. **frontmatter 解析**：索引时解析文件头 YAML（title/tags/date 等），`kb_documents` 加 `frontmatter` JSON 列。
2. **标签**：`kb_tags(note_id, tag)` 表 + 笔记树顶部标签过滤条；`#tag` 行内写法与 frontmatter `tags:` 双入口，都归一入库。
3. **双链**：索引时正则提取 `[[...]]`（支持 `[[路径|别名]]`），`kb_links(from_id, to_path, to_id)` 表；NotesView 预览内 `[[...]]` 渲染为可点击跳转；右栏"反向链接"面板列出谁链到了当前笔记（ Obsidian 核心体验）。
4. **AI 工具**：`list_tags`、`find_backlinks`，让 AI 能回答"哪些笔记引用了 X"。

**验收**：`[[` 输入有补全、点击跳转、反向链接面板可用；`search_notes` 检索结果可按标签过滤。

### 四期：索引质量（增量与性能）

**目标：大库（数千文件）下索引又快又省。**

1. **增量索引**：利用已存的 `file_mtime` 只重index 变化文件，替换全量 `deleteDocs` 重建（indexer.ts:23）；fs.watch 单文件事件直接映射到单文档更新。
2. **embedding 增量**：只对新/变更 chunk 调嵌入（现有 `embedding IS NULL` 逻辑天然支持，删掉的 chunk 要连带清理）。
3. **索引后台化**：`index-worker.ts`（子进程版）作为唯一索引入口，UI 只显示进度，主进程不再承担大库全量扫描。

## 4. 数据模型变更汇总

| 变更 | 内容 | 期次 |
|------|------|------|
| `kb_chunks` 增列 | `title`/`rel_path` 上下文（或块首拼接） | 一期 |
| `kb_documents` 增列 | `frontmatter`（JSON TEXT） | 三期 |
| 新表 `kb_tags` | `note_id`, `tag` | 三期 |
| 新表 `kb_links` | `from_id`, `to_path`, `to_id`（nullable，悬链不解析） | 三期 |
| `kb_documents.file_mtime` | 已有，从"存了没用"变成增量索引依据 | 四期 |

`prj_projects`（笔记库表）结构不动。

---

## 5. 风险与取舍

- **编辑器深度**：CodeMirror/Monaco 引入会显著增加包体，一期用 `textarea` 验证需求，确认高频使用再升级——避免一步到位的过度工程。
- **向量检索的模型依赖**：hybrid 依赖用户配置 embedding 模型（Ollama 或 API），没配就自动降级纯 BM25，不把硬依赖埋进主路径。
- **外部编辑冲突**：用户用 VSCode 改文件与应用内编辑并发——mtime 乐观锁兜底，冲突时不静默覆盖。
- **`.trash/` 目录**：删除进回收目录并加入索引忽略列表，避免"删了又被搜出来"。

---

## 6. 落地顺序建议

```
一期（检索接线）→ 二期（编辑器）→ 三期（结构层）→ 四期（增量索引）
```

一期是纯接线、风险最低、立刻改变"AI 用不用得上笔记"的体感，建议最先做。
