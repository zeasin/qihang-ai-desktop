# 启航AI工作台 —— 功能设计与使用说明（单引擎方案：pi）

> 本文档描述基于 **单一 AI 引擎（pi）** 的产品形态：启航AI工作台——一个围绕本地项目库工作的个人 AI 智能体，本地优先。包含功能设计、架构说明与完整使用指南。
>
> 引擎说明：工作台内置 `@earendil-works/pi-coding-agent`（当前 1.4.x），SDK 直接运行在 Electron 主进程内；所有对话、飞书、定时任务共用这一条链路，本地工具以 customTools 原生注入。

---

## 1. 产品定位

**一个围绕本地项目库工作的个人 AI 智能体：对话即查、任务即执行、数据即分析，一切记录留在本机；飞书与手机是它的移动入口，随时指挥、随时接收。**

| 支柱 | 说明 | 对应功能 |
|------|------|----------|
| 📁 **主体：本地项目库** | 「项目」就是你磁盘上的一个文件夹（笔记库 / 代码库 / 资料库都行），Markdown 目录即数据主体，AI 直接读取、写入目录里的文件作答；对话、任务、日报全部以项目为归属 | 项目库 / 笔记 / 今天页 |
| 🧠 **智能面：助理 + 数据分析** | 个人助理（对话、待办、提醒、日报）+ 数据整理与分析（数据集、笔记提炼、报告生成）；分析产出落回项目库、变成任务、推到飞书，形成闭环而非独立 BI | 对话 / 任务 / 数据 / 技能 |
| 📶 **触达面：飞书 + 手机** | 移动指挥入口（飞书派活、卡片确认、「接着问」续聊；手机 App 中继远程对话）+ 无人值守的推送回路（日报、提醒、任务结果送达）；与桌面端共用同一条引擎链路 | 飞书 Bot / 中继 / 日报 |

> 触达面是场景包，不是前提：断开一切外部连接，工作台依然完整可用。
> 外部系统经 MCP 接入为规划中的演进方向（见 4.3）：外部工具与内置工具同面，对话即操作。

---

## 2. 核心设计原则

| # | 原则 | 设计落点 |
|---|------|----------|
| 1 | **单一引擎** | 只保留 pi 一个引擎：对话、飞书派活、飞书追问、定时日报、AI 工具箱全部同链路，行为一致、无需切换与回退 |
| 2 | **用户零安装** | pi SDK 随应用打包（纯 JS，无原生二进制），主进程内`import()` 动态加载，不 spawn 任何子进程；用户无需安装 CLI/Node |
| 3 | **本地优先** | 笔记、数据集、对话记录、会话历史全部留在本机 |
| 4 | **移动指挥** | 飞书 Bot 是一等入口：手机下发任务、收日报、看分析、做确认；无人值守场景与桌面端同一条 pi 链路 |
| 5 | **连接器架构** | 工作台作为 MCP 客户端接入外部系统：外部工具经 MCP 进入引擎工具面，与 customTools 直注的内置工具同面共存；内置工具不经 MCP 暴露 |
| 6 | **开箱即用** | 「设置 → 💬 对话模型配置」一处配置即生效（OpenAI 兼容接口 / Ollama 本地模型），保存后热重载无需重启 |

## 3. 总体架构

```
┌───────────────────────── Electron 主进程 ─────────────────────────┐
│                                                                    │
│  5 个 agent 入口：主对话 / 飞书 Bot / 飞书追问 / AI 工具箱 / 定时日报 │
│        │                                                           │
│        └─ 全部 ──► pi 引擎（runPi：SDK 直挂主进程，无子进程）          │
│                 ├── 模型：ModelRuntime（~/.pi/agent/models.json│                 │   + auth.json），应用内「对话模型配置」读写并热重载  │
│                 ├── 会话：SessionManager + createAgentSession，      │
│                 │   会话级模型切换、同会话 prompt 串行                │
│                 ├── 工具：customTools 原生注入（笔记库/数据集/任务/  │
│                 │   提醒/联网搜索），按会话上下文动态组装              │
│                 ├── 流式：message_update 增量 + tool_execution 事件│                 └── 可靠性：同会话串行链、可选硬超时、中止、全链路日志│
│                                                                    │
│  （演进）MCP 接入面：外部系统走 remote MCP 接入，与内置工具同面     │
└────────────────────────────────────────────────────────────────────┘
```

**单引擎要点**

| 维度 | 说明 |
|------|------|
| 引擎 | pi（`@earendil-works/pi-coding-agent`），主进程内SDK 动态 import |
| 进程开销 | 无子进程、无端口分配、无健康探测；会话对象按 sessionId 缓存复用 |
| 本地工具 | customTools 原生注入（笔记库/数据集/任务/提醒/联网搜索）✅ |
| 全部入口 | 主对话、飞书 Bot、飞书追问、定时日报、AI 工具箱共用一条链路 |
| 安装包体积 | 相比捆绑 CLI 方案显著更小（打包时剔除各云厂商 SDK：@google/genai、@anthropic-ai/sdk、@aws-sdk 等） |
| 升级方式 | 改`package.json` 里的 pi 版本号 → `npm install` → 回归对话/工具/日报三条链路 |

## 4. 功能设计

### 4.1 既有功能（个人智能助理能力面，全部保留）

> 以下模块构成「个人智能助理」的完整能力面：AI 帮你记笔记、整理业务数据、跟任务、守日程、写汇报——不需要连接任何外部系统。

| 模块 | 说明 |
|------|------|
| 💬 AI 对话 | 多轮对话、图片粘贴/上传识别、流式输出、模型切换；内含「对话 / 知识库 / 概览」三个 Tab；每个会话可选笔记库 |
| 📚 知识库 | 多笔记库切换、Markdown 浏览预览、文件名搜索、基于笔记回答问题 |
| 📊 概览 | 统计卡片、综合日报、待办、提醒、待处理记录看板 |
| 🔔 任务中心 | 定时/循环任务（每天/每周/每月/Cron），每个任务归属一个笔记库，结果自动存所属库、可选推送飞书 |
| 🗃️ 数据集 | 多数据集、自定义 Schema、内置模板、AI 业务分析、JSON/URL 导入 |
| 📅 提醒 | 每日/每周/每月/每年/一次性提醒，系统通知 + 飞书推送 |
| 🔧 工具箱（beta） | PPT/HTML 演示大纲、周报日报、思维导图、文案、网站抓取、图片生成（笔记素材取全部库） |
| 🔗 飞书集成 | Webhook 推送；配置 Bot 后飞书内直接对话、下发任务；多项目时每条消息先弹项目选择卡片确认落点（见 5.4 / 5.5） |
| 📋 自动日报 | 定时汇总**全部笔记库 + 数据集**、任务、对话生成 AI 日报并推送 |
| ⚙️ 笔记库管理 | 设置 → 📚 笔记库：多库增删/重命名/换目录/设默认/按库重建索引；一个库都没有时 AI 功能门禁提示先添加 |

#### 多笔记库口径（✅ 已实现）

- **库即项目**：每个笔记库是「设置 → 📚 笔记库」里的一条记录（名称 + 本地目录），可添加多个，其中一个为默认库；索引按库独立重建（`kb_documents.project_id` 归属），互不影响
- **默认库指针**：`config.notesDir` 恒等于默认库目录，由库管理操作自动同步，飞书链路因此零改动
- **谁用哪个库**：桌面对话按会话选库（记住每个会话上次的选择）、任务创建/编辑时选所属库（执行与追问都基于该库）、知识库页顶部切库；飞书对话、派活按每条消息确认的项目落库（多项目时先弹卡片确认，选中项目写入会话默认上下文，单项目直接落唯一项目）；综合日报、概览统计、工具箱周报/PPT 聚合全部库 + 数据集
- **门禁**：从「未配置笔记库」改为「一个笔记库都没有」；添加第一个库即解锁全部 AI 功能

### 4.2 单引擎能力（✅ 已实现）

- **统一链路**：主对话、飞书派活/追问、定时任务日报、AI 工具箱全部经`runPi`，不存在第二套引擎分支
- **模型管理**：应用内「对话模型配置」直接读写 `~/.pi/agent/models.json`（多条 provider、每条多个模型），保存后 `ModelRuntime` 热重载立即生效；未显式选模型时同步 `settings.json` 的默认模型为应用内第一个可用模型
- **模型记忆**：对话页与任务追问页各自记忆上次选择的模型（localStorage），按引擎维度记忆的历史键已统一为 pi
- **工具注入**：会话创建时按上下文组装 customTools（数据集查询/项目文件、笔记库读写、任务/提醒、日报查询、联网搜索），同一会话内工具集固定
- **流式与工具事件**：`message_update` 增量转对话流，`tool_execution_start/end` 转工具执行状态；同会话 prompt 串行，避免并发打断
- **可靠性**：单轮可选硬超时（超时即中止并报错）、模型切换失败降级为默认模型、`[PiAgent]` 全链路日志

### 4.3 演进能力（🚧 规划中）

#### 🤖 AI 运行时卡片（设置页增强）

- 模型可用性与默认模型同步状态的直观展示
- 一键「测试连通性」（复用 `pi:config:test`，直连 OpenAI 兼容端点 ping）

#### 🎁 模型引导（首启 Onboarding）

无可用模型时，发消息触发引导，指向「设置 → 💬 对话模型配置」：

- **路径 A（本地离线）**：Ollama 本地模型，填服务地址与模型名即可
- **路径 B（云端）**：任意 OpenAI 兼容接口（DeepSeek、智谱、硅基流动等），填 Base URL / API Key / 模型名，可先「测试」验证

#### 🔌 MCP 服务器（新增设置卡片）

工作台作为 **MCP 客户端**接入外部 MCP server：连接后 server 的工具以 `mcp__<server>__<tool>` 进入引擎工具面，与内置工具同面共存；**内置工具保持 customTools 直注**（TypeBox schema、流式工具事件是 pi 一等公民），不经 MCP 暴露。

| 行 | 说明 |
|----|------|
| MCP 服务器列表 | 任意 MCP server（Streamable HTTP）：URL + 自定义 Header + 启用开关 + 连接测试（list_tools 验证连通与工具清单）；连接状态变更时重建受影响会话（会话工具集在创建时固定） |

- 传输：Streamable HTTP（pi MCP 客户端仅支持 stdio / Streamable HTTP，无 SSE），连接前确认对端使用相同传输协议
- 自定义 Header 勿填 `Accept` / `Content-Type` 等协议头（框架管理）
- Token 与模型 API Key 同等安全水位，明文存于本机 config.json

**M1.6 实施设计（接入方案）**

单引擎红利：引擎侧挂载一次，对话 / 飞书 / 追问 / 定时任务 / 工具箱 5 个入口全部生效。

```
设置 → MCP 服务器卡片 ──► config.json (mcpServers)
                              │
            services/mcp.ts（新增：配置读写 / 连接测试 / 状态）
                              │ loadConfig 注入
            pi-agent getSession ──► createMcpExtension() ──► bindExtensions()
                              │
            工具以 mcp__<server>__<tool> 进引擎 registry，与内置工具同面
```

| 改动点 | 设计 |
|--------|------|
| 引擎挂载（pi-agent.ts） | `DefaultResourceLoader` 增加 `extensionFactories: [createMcpExtension({ loadConfig })]`；`createAgentSession` 后**必须** `await session.bindExtensions({})` 触发连接（连接发生在 session_start，SDK 不自动触发） |
| 配置注入 | 应用 config.json 新增 `mcpServers`（id / name / url / token / enabled / exposure），经 `loadConfig` 映射为 SDK 的 `LoadedMcpConfig`；不直接写 `~/.pi/agent/mcp.json`，避免与用户 pi CLI 的配置互相污染 |
| 连接测试 | 直接用 `@earendil-works/pi-mcp`（McpClient + StreamableHttpTransport）list_tools，返回工具数与清单；「测试」按钮即此，顺带验证对端传输协议兼容，不建会话 |
| 会话生命周期 | 会话工具集在创建时固定：保存配置或启停切换后，按「启用中的 server 指纹」变化对受影响会话 `resetPiSession` 重建，否则新工具不生效 |
| UI 与 IPC | 卡片字段：名称 / URL / Token（Bearer）/ 启用 / 暴露方式（默认 direct）/ 测试（显示工具数）；IPC：`mcp:list` / `mcp:save` / `mcp:test` / `mcp:status` |

实现陷阱（pi SDK 1.4.0 调研确认）：

- **默认 exposure 是 `codemode`**：工具只进 codemode 脚本通道，模型声明里完全不可见——必须显式 `exposure: "direct"`；工具很多的 server 后续可切 `deferred`（需另挂 `createToolSearchExtension()`）
- **首轮等待**：连不上的 direct server 会让首轮 prompt 最多等 `startupWaitMs`（默认 10s）——连接测试先行、禁用的 server 不注入
- **401 触发 OAuth**：HTTP 对端回 401 时 SDK 会走浏览器 OAuth 授权；用 headers 传 Bearer Token 则不触发
- **ESM 动态加载**：MCP 扩展随 pi SDK 一起经既有 `loadSdk()` 机制动态 import，无新增打包问题

阶段计划：

| 阶段 | 内容 | 量 |
|------|------|----|
| Phase 0 PoC | 临时脚本验证「挂载 → bindExtensions → getActiveToolNames」链路与 McpClient 测试 API、对端传输 | 半天 |
| Phase 1 MVP | services/mcp.ts + pi-agent 挂载 + 4 个 IPC + 设置卡片 + 会话重建 | 1~2 天 |
| Phase 2 打磨 | 暴露策略（deferred）、连接状态展示（侧栏芯片复用飞书模式）、错误兜底、提示词补充 | 按需 |

#### 🔗 外部服务连接

设置 → MCP 服务器 → 填服务地址与凭据（URL / Token 等）→ 连接测试 → 完成绑定。绑定后该服务的工具自动进入 AI 可用列表，对话即可调用。

## 5. 使用指南

### 5.1 安装与首次启动

1. 双击安装包安装（AI 内核已内置，无需安装 Node、CLI 或任何依赖）
2. 启动后完成两项基础配置：
   - **模型**：设置 → 💬 对话模型配置（OpenAI 兼容接口或 Ollama 本地模型）
   - **笔记库**：设置 → 📚 笔记库，添加一个或多个 Markdown 文件夹（第一个自动成为默认库）；对话与任务按库选用，飞书固定用默认库
3. 进入「AI」页开始对话；输入框左下角可切换模型

### 5.2 日常使用

- 「把这段客户名单整理成数据集，字段：名称、地区、等级、跟进状态」→ AI 自动建数据集、逐条写入
- 「把我刚才说的这几件事记成待办，下周一开始跟进」→ 写入任务中心并设提醒
- 「读一下笔记库里上个月的周报，汇总成本月小结」→ 知识库检索 + 汇总成文
- 「每天晚上 9 点提醒我过一遍今天的待办」→ 创建周期提醒
- 随手记的 Markdown 笔记、粘贴的 JSON 数据，都留在本机，AI 随时可查

**日常操作入口：**

- **对话**：AI 页输入问题，AI 按需自动调用本地工具（查数据集、读写笔记、联网搜索）后回答；输入框上方 📚 下拉可切换本会话使用的笔记库
- **知识库**：AI 页切到「知识库」Tab，让 AI 基于你的笔记回答；顶部下拉切换笔记库
- **任务**：任务页创建定时/循环任务时选择所属笔记库，结果自动落该库并可推送飞书
- **数据集**：数据页管理结构化数据（客户、项目、Bug 等），AI 可直接查询与写入
- **提醒与日报**：提醒页设置周期提醒；每日日报自动汇总推送

> 所有入口（对话/ 追问 / 定时任务 / 飞书）都具备完整本地工具能力，无需区分引擎。

### 5.3 手机指挥（飞书）

- 配置飞书 Bot 后（设置 → 飞书集成），在飞书里 @助手 即可：
  - 随时提问：「A 店铺近 7 天销量趋势？」
  - 下发任务：「整理本周客户跟进清单」
  - 接收日报、提醒与任务结果
- 飞书/定时任务与桌面端同一条 pi 链路，headless 已处理，AI 执行全程不弹审批阻塞

### 5.4 飞书卡片交互设计（2026-10-31 起）

> 核心策略：**每条消息先确认落点，再执行**。会话绑定不再静默生效，而是变成卡片上的默认选项——上下文始终由用户点一下确认，绝不静默把消息落进某个项目（单项目除外，没得选即不问）。

**三类卡片**

| 卡片 | 何时出现 | 内容与交互 |
|------|----------|------------|
| 📂 请选择项目 | 消息未明确指定项目且项目数 > 1（**含已有会话绑定**的情况） | 项目按钮组（按钮序号与卡片文字列表严格一致）；已绑定时首个按钮为「就用当前项目「X」」（沿用绑定项目执行本条，仍开新会话）；底部提示可回复序号或「/项目 名称」 |
| 🤖 AI 结果卡片 | 任务执行完成 | AI 回复正文 + 底部「本条已发到「X」」标注 + 「💬 接着问」按钮（点后直接回复即可续聊这条对话，不再每条消息新开会话） |
| 状态卡片 | 全程反馈 | 已接单（项目：X）、项目已切换、处理出错、工作单已记录等 |

**交互方式（按钮之外的所有兜底）**

- 点卡片按钮（推荐）：点击即派活，立刻看到绿色轻提示「已派活到「X」，执行中…」
- 回复序号：`2` 或 `/项目 2`（序号 = 卡片列表里的指派编号）
- 回复项目名：`/项目 笔记库`；行内标记 `[笔记库：项目名]` 只对这一条生效
- 追问最近一条对话：`继续 把刚才的报告补充一段风险说明`；或点结果卡片「💬 接着问」后直接回复，接在那条对话后面继续问

**内部派活机制**

- 卡片按钮点击不另起实现，而是转成一条内部指令 `/项目#<项目id>` 的伪消息，交回与普通消息完全相同的派活链路（挂起正文取回、会话绑定、会话落库复用同一处代码）
- `/项目#<id>` 与普通 `/项目 N` 的区别：普通指令是「列表序号优先、项目 id 兜底」，项目数 ≥ id 时会落到列表第 N 个；内部指令严格按项目 id 解析，专供卡片按钮使用
- 「💬 接着问」：点结果卡片按钮后，本会话进入那条对话的续聊模式（滑动 30 分钟窗口，每次续聊刷新），此后的普通消息都接在该会话后面继续对话，不再每条新开会话；发 `/` 开头的命令或点项目选择按钮即退出该模式开始新话题
- 点击选中的项目写入会话默认上下文，作为下一条消息卡片上的默认选项（仍需确认一次）

**回调响应机制（为什么点了立刻有提示）**

- 飞书要求卡片回调 **3 秒内**响应，否则客户端弹「目标回调服务超时未响应」
- 应用收到回调后只做快速校验（项目是否存在、对话是否存在），立即返回 toast 响应；真正的派活转后台执行，与 AI 任务的分钟级耗时解耦
- 反馈链路：toast 轻提示 → 「已接单（项目：X）」消息 → AI 结果卡片

### 5.5 飞书卡片回调配置（开通步骤）

卡片按钮依赖飞书开放平台的「卡片回传交互」回调，需一次性开通：

| 步骤 | 操作 |
|------|------|
| 1 | 登录[飞书开放平台](https://open.feishu.cn/)，进入你的自建应用 → 「开发配置」→「事件与回调」 |
| 2 | 切到「回调配置」Tab，订阅方式选择「**长连接**」（推荐；无需公网域名与加密策略，桌面端经官方 SDK 直连） |
| 3 | 在「已订阅的回调」中添加「**卡片回传交互（card.action.trigger）**」 |
| 4 | 创建版本并发布（或按平台提示生效），重启桌面端使长连接生效 |
| 5 | 验证：在飞书里给机器人发一条消息 → 点弹出的项目选择卡片按钮，应立即看到「已派活」绿色提示 |

> - 未订阅回调时按钮点击无响应，但**文字回复不受影响**（序号 / `/项目 名称` 照常可用），功能不丢。
> - 点按钮报「目标回调服务超时未响应」是旧版本应用把任务执行等在了回调里导致的，升级/重启应用即可；该报错不代表任务没派出（「已接单」出现即已派活）。

## 6. 方向自检：什么变了，什么没变

**变了（3 件事）**

1. 底座：单 pi → 双引擎并存（pi + opencode）→ **回归单引擎 pi**（1.4.x），去掉运行时切换与 opencode 子进程托管
2. 能力对齐：所有入口统一具备完整本地工具（此前 opencode 分支无工具）
3. 定位：围绕本地项目库的**独立完整个人 AI 智能体**（助理 + 数据分析），外部系统经 MCP 接入作为扩展场景

**没变（全部既有价值）**

数据闭环五步（采集→分析→建议→执行→推送）、本地优先、飞书集成、全部既有功能模块、独立应用形态、pi 引擎上的工具能力。

**去掉双引擎后的收益**

| 项 | 说明 |
|------|------|
| 安装包瘦身 | 不再捆绑 opencode 二进制（曾 +约 180MB）；pi 侧云厂商 SDK 在打包时剔除 |
| 维护面减半 | 不再需要双份事件流适配、模型映射、配置同步、子进程托管与自愈逻辑 |
| 行为一致 | 对话、飞书、定时任务、工具箱的能力与工具面完全统一，不再出现「某引擎无本地工具」 |
| 升级路径清晰 | 只跟pi SDK 版本（1.4.x），回归面= 对话 + 工具 + 日报三条链路 |
