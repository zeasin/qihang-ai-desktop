# 中继服务协议 · 桌面端 ↔ 中继

> 版本：v1（对应桌面端 `electron/services/relay-client.ts`）
> 范围：本文档只覆盖**桌面端 ↔ 中继**这半边协议。移动端 ↔ 中继（配对 claim/exchange、移动端 WS、镜像读取）的契约由 relay-server 与手机 App 约定，另行成文。
> 可执行规范：`scripts/smoke-relay.cjs` 内置了一个假中继，逐帧校验本文全部约定；任何语言实现的中继只要通过该冒烟测试，桌面端即可对接。

## 1. 拓扑

桌面端与移动端都躲在 NAT 后，彼此无法直连。两者各自**出站**连接同一个中继，中继按 deviceId 把两条 socket 对接起来。

- 桌面端只作为 HTTP + WS 客户端，**不监听任何端口**。
- 桌面端关机时，移动端读中继里由 `sync.*` 事件维护的数据镜像（能看不能发）。
- 桌面端是唯一事实来源；中继只做镜像存储与消息转发。

中继地址只填到域名或 `IP:端口`，不带路径（桌面端自行拼接 `/relay/...`）。

## 2. 通用约定

- 所有请求/帧均为 UTF-8 JSON。
- 设备身份三元组由桌面端首次启动时生成并持久化：`deviceId`（UUID 去连字符）、`token`（设备密钥，一经生成不变）、`password`（移动端配对密码，6–64 位，中继侧全库唯一）。
- 需要`X-Relay-Token` 鉴权的接口，头部值为设备 `token`。
- 时间戳一律 epoch 毫秒。
- 所有响应统一形状：`{ ok: boolean, ... }`，失败时 `{ ok: false, error: string }`。

## 3. REST 接口

### 3.1 探活

```
GET /relay/health
```

响应（中继本人必须回这个字段组合）：

```json
{ "ok": true, "service": "relay-server", "dbStatus": "UP", "devicesOnline": 0 }
```

桌面端保存中继地址前会探活：`service !== 'relay-server'`、返回 HTML（nginx 未转发）或 `ok !== true` 一律判失败。

### 3.2 设备注册

```
POST /relay/device/register
Content-Type: application/json

{ "deviceId": "...", "token": "...", "name": "设备名",
  "password": "...（未设置时省略）", "remoteEnabled": true }
```

响应：`{ "ok": true, "deviceId": "..." }` 或 `{ "ok": false, "error": "..." }`。

**必须容忍重复注册**：桌面端每次 WS 重连前都会先重新注册（中继的 token 表允许是内存态，重启后丢失，靠重注册恢复）。

### 3.3 配对密码校验

```
POST /relay/device/password
{ "deviceId": "...", "token": "...", "password": "..." }
```

- 成功：`{ "ok": true }`
- 密码与库内已有设备冲突：`{ "ok": false, "error": "..." }`（桌面端被拒时本机不落任何状态）
- 旧版本中继无此接口：返回 HTTP 404，桌面端提示更新中继

### 3.4 在线移动端会话

```
GET /relay/device/{deviceId}/clients
X-Relay-Token: <token>
```

响应：

```json
{ "ok": true, "clients": [ {
    "sessionId": "...", "clientId": "...", "name": "...",
    "platform": "...", "connectedAt": 1700000000000, "lastActiveAt": 1700000000000
} ] }
```

以中继 WS 会话表为准（桌面端本机 socket 可能在重连间隙断开）。

### 3.5 踢下线

```
POST /relay/device/{deviceId}/clients/{sessionId}/kick
X-Relay-Token: <token>
```

响应 `{ "ok": true }`。被踢的移动端收到 close reason `kicked` 后应停止自动重连。

### 3.6 镜像读取（桌面端对账用）

```
GET /relay/mobile/{deviceId}/projects   → [{ "projectId": "...", ... }]
GET /relay/mobile/{deviceId}/sessions   → [{ "sessionId": "...", ... }]
X-Relay-Token: <token>
```

桌面端不消费其余字段，只取 id 清单做删除收敛（见 §6.4）。

## 4. WebSocket 通道

```
GET ws(s)://{relay}/relay/ws/device?deviceId=..&token=..
```

- 握手失败（如 invalid token）：桌面端 5 秒后先重新 `register` 再重连。
- 被动断开：同样 5 秒重连循环，永不过期。
- 桌面端主动 `stop()`（开关关闭）：中继应拒绝该设备的新握手并踢掉在线移动端。
- 心跳双通道：
  - 应用层：桌面端每 20 秒发 `{ "type": "event", "event": "heartbeat", "data": { "ts": ... } }`，中继须回 `heartbeat:ack`（中继可据此数入站活动）。
  - 传输层：桌面端同时发 WS `ping`，60 秒内收不到 `pong` 则强制断开重连。

## 5. 消息信封

WS 上所有帧统一信封（缺省字段可省略）：

```json
{
  "id": "请求相关联 ID（request/response/error 必带）",
  "type": "request | response | error | event",
  "method": "RPC 方法名（request）",
  "params": {},
  "result": {},
  "error": "错误文本（error）",
  "event": "事件名（event）",
  "data": {},
  "timestamp": 1700000000000
}
```

- 非 JSON 帧直接忽略，不断链。
- RPC 应答必须回带原 `id`；`type: "error"` 的 `error` 为人类可读文本。
- 未实现的 method 回 `{ id, type: "error", error: "unknown method: <method>" }`。

## 6. 桌面端 → 中继（事件帧，`type: "event"`）

### 6.1 心跳

见 §4。

### 6.2 数据同步事件（中继落 MySQL 镜像）

| 事件 | 时机 | data |
|---|---|---|
| `sync.project` | 连接建立全量 / 项目增改 | 见 a |
| `sync.projectDeleted` | 项目删除、上线收敛 | `{ projectId }` |
| `sync.chatSession` | 连接建立全量 / 会话增改 | 见 b |
| `sync.chatSessionDeleted` | 会话删除、上线收敛 | `{ sessionId }` |
| `sync.chatMessage` | 单条消息增量（回答收口等） | 见 c |
| `sync.task` | 连接建立全量（最近 1000 条）/ 任务增改 | 见 d |
| `sync.full` | 连接建立全量的收尾帧 | `{ messages: { [sessionId]: message[] } }` |

a. **project**：

```json
{ "projectId": "字符串", "name": "...", "description": "本机目录或描述", "status": "active" }
```

注意：含 `type=code` 的代码库（桌面端普通列表会滤掉，镜像不滤）。

b. **chatSession**：

```json
{ "sessionId": "...", "projectId": "字符串或 null", "title": "...",
  "adapterId": "pi", "modelId": "字符串或 null", "status": "active",
  "kind": "chat", "taskId": null, "runId": null, "ended": 0,
  "lastActiveAt": 1700000000000 }
```

字段名按三端约定（`sessionId`/`adapterId`），时间戳 epoch 毫秒。挂在库外的历史会话（`project_id` 为空，如飞书会话）也进镜像。

c. **chatMessage**：

```json
{ "sessionId": "...", "messageUid": "<sessionId>_<消息行id>",
  "role": "user | assistant", "content": "...", "thinking": "...",
  "status": "done", "modelId": null, "tokens": 0,
  "durationMs": 0, "createdAt": 1700000000000 }
```

d. **task**：

```json
{ "taskId": "字符串", "projectId": "字符串或 null", "title": "...",
  "description": "...", "status": "pending",
  "priority": "low | medium | high",
  "assignee": null,
  "scheduleJson": "定时信息 JSON 串或 null",
  "nextRunAt": 1700000000000 }
```

桌面端内部优先级 `mid` 上送前归一为 `medium`。

### 6.3 对话流式事件（转发给在线移动端）

桌面端渲染层的 `chat:*` 通道按 `chat:` → `chat.` 前缀映射原样转发：

| 事件 | data |
|---|---|
| `chat.delta` | `{ sessionId, text }`（增量正文） |
| `chat.status` | `{ sessionId, text }`（阶段提示） |
| `chat.thinking` | `{ sessionId, text }`（思考过程） |
| `chat.done` | `{ sessionId, durationMs? }` |
| `chat.error` | `{ sessionId, text }` |

`chat.done` 时桌面端随后会补推 `sync.chatSession` + 末尾 2 条 `sync.chatMessage`，把该轮问答落进镜像。

### 6.4 删除收敛语义（重要）

中继**没有**「不在全量清单里就删」的语义，镜像只增不删。桌面端全量同步后会拉 §3.6 的清单对账，对中继有而本地已无的项目/会话补发 `sync.projectDeleted` / `sync.chatSessionDeleted`。中继照单执行删除即可。漏掉这一条，移动端会点进幽灵会话。

## 7. 中继 → 桌面端

### 7.1 事件帧

| 事件 | data | 桌面端行为 |
|---|---|---|
| `heartbeat:ack` | `{ ts }` | 刷新链路活跃时间 |
| `test:message` | `{ ts, name }` | 弹系统通知（移动端「发测试消息」走事件不走 RPC） |
| `test:ack` | — | 旁路给渲染层 |
| `mobile:connected` | — | 旁路给渲染层 |

### 7.2 RPC（`type: "request"`，中继把移动端请求原样桥接过来）

| method | params | result | 说明 |
|---|---|---|---|
| `chat.create` | `{ projectId?, title?, agent? }` | 会话视图 | 桌面端建会话并回推 `sync.chatSession` |
| `chat.send` | `{ sessionId, text, projectId?, title?, agent?, images? }` | `{ ok: true }` **立即回执** | 正文经 `chat.delta/status/done` 事件流回传，避免 RPC 超时；会话已被删时按原 id 重建（要求 projectId 存在） |
| `chat.stop` | `{ sessionId }` | `{ ok: true }` | 中止该会话正在跑的一轮 |
| `chat.switch-agent` | `{ sessionId, agent }` | `{ ok: true }` | 切引擎并回推 `sync.chatSession` |
| `chat.select-model` | `{ sessionId, modelId }` | `{ ok: true }` | `modelId` 为 `"auto"` 时清空指定 |
| `chat.list-models` | `{}` | 模型列表数组 | |
| `chat.interactions` | `{}` | `[]` | 桌面端内核不向用户反问，恒空（占位） |
| `chat.answer` | — | 恒报错 | 同上，明确拒绝而非静默成功 |

handler 抛错时桌面端回 `{ id, type: "error", error: "<消息>" }`。

## 8. 状态机与边界情况

- **开关语义**：`remoteEnabled=false` 或未设密码时，桌面端不建 WS、不发任何同步帧；只维持 REST 注册（上报状态）。
- **帧写入**：socket 未 OPEN 时事件帧直接丢弃，不排队、不报错（`send` 返回 false 即可）。
- **中继重启**：token 表可丢。桌面端重连前自动重注册，新中继须接受「未见过 deviceId」的注册并建行。
- **幂等**：`sync.chatMessage` 按 `messageUid` upsert，重复推送不得产生重复行；全量与增量可能交叉到达。
- **sync.full 收尾**：消息按会话**整段替换**（先清该会话旧消息再写入本帧清单），不做逐条 diff。

## 9. 验收清单

实现方跑 `npx electron scripts/smoke-relay.cjs`（假中继即测试基准），须全绿：

- health 探活字段、register/password 请求形状
- 全量同步帧形状（§6.2 各 payload 字段、epoch 毫秒、messageUid 幂等）
- 上线补删（§6.4）
- RPC 分发：已知方法回 response、未知方法回 error、事件可主动下发
- 心跳帧与 ack
