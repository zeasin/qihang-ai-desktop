1视觉语言是「默认的」

靛蓝 #6366f1 + 石板灰 #f8fafc 是 Tailwind 默认配色。放眼同类 AI 工具，这套配色是最没有辨识度的一种。产品叫「启航」，界面里没有一点航海感。

2没有明暗模式

全仓库搜不到 prefers-color-scheme 或 data-theme。而这个产品有「手机指挥电脑」的特性——用户大概率在晚上看日报、看任务结果。

3每个页面都是同一个模子

顶栏 + 一堆白卡片浮在浅灰底上。10 个页面共用这一种布局，用户切换页面时得不到「空间在变化」的感觉，只能靠文字判断自己在哪。

4样式没有收口

global.css 里有变量，但各视图仍在硬编码色值：global.css:79-83 的 badge 一组浅灰、NotesView.vue:421 又写死 --primary-dark。ConfigView 单文件 74KB，改一个主色要跨十几个文件。

5图标是 emoji 而不是图标

全篇 📚💬🔧⚡📁🗨️⏳☐📌🗓️。它们是插画不是图标：没有统一线宽、不能继承颜色状态、在小尺寸下糊成一团。

02

四个方向共同遵守的底线

不管选哪条，这些都不做。改版最容易失败的原因不是不好看，而是旧的毛病带进了新的皮。

不重写业务

路由、IPC、10 个页面的功能逻辑全部保留。这是一次视觉与信息架构的重做，不是重构项目。

一套可换肤的令牌

所有颜色、圆角、阴影、字号收敛到 CSS 变量，主色切换只需改一处。

换掉全部 emoji

统一用 Lucide 线性图标（1.75px 描边），继承 currentColor。

密度只增不减

侧栏从 68px 图标条升级为带文字的导航，但对话页仍保留双栏工作流。

明暗双版本

每个方向都给出亮/暗两套配色，而不是把暗色当补丁。

中文排版优先

正文行高 1.7–1.8，字号不小于 14px；数字用等宽字体对齐。

05

我的建议

如果由我决定，会这么组合——不是四选一，而是取各方向最强的那一块。

★
选 A 的视觉骨架，用 B 的排版手感，收 D 的可用性细节

「航海舱」提供记忆点，「纸墨」保证中文长文本读得舒服，「温柔仪表盘」保证交互细节经得起日常使用。

三段式组合
视觉骨架 ← A深海蓝 + 黄铜的仪表体系，深色为默认、亮色为「白昼模式」。导航重做为带文字的两段式分组，数据栏常驻右侧。
阅读排版 ← B笔记预览、对话回答、日报正文全部走宋体 + 1.85 行高；数字与元信息用等宽。中文界面最忌讳的正是「截图式的英文排版」。
交互细节 ← DBento 概览、圆角 12–14px、柔和阴影、悬停微浮起、快捷键提示。功能该有的一个不少，但不再像一张 Excel 表。
落地顺序
  1. 第 1 步 · 令牌层：把 global.css 重写成双主题令牌（明/暗 + 4 组语义色），各视图里硬编码的色值全部换掉。这一步不改任何布局，但立刻换掉「默认 Tailwind 感」。
  2. 第 2 步 · 图标层：引入 Lucide，把全仓 emoji 图标替换为线性图标，侧栏从 68px 图标条升级为带文字导航。
  3. 第 3 步 · 骨架层：重做 App.vue 外壳（标题栏 + 导航 + 内容区），统一 10 个页面的页头、间距、卡片规格。
  4. 第 4 步 · 重点页：优先重做「概览」（Bento）与「对话」（三栏折叠 + 阅读列），这两页占用户停留时间 80%。
  5. 第 5 步 · 排版层：给 Markdown 渲染、对话消息、笔记预览补一套「纸墨」排版规则（宋体、行高、代码块、表格）。
  6. 第 6 步 · 收尾：补空状态、加载态、错误态；做一次明暗双主题的视觉走查；更新 README 截图与更新日志。
提案基于 qihang-ai-desktop v0.9.0 现有实现（10 个视图 / 11 个组件 / 单引擎 pi）。选定方向后可按上述六步逐个落地，每步都可独立验收。
