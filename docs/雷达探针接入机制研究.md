## 一、一句话结论

**雷达探针接入智能体 = 实现 `HubCollector` 四方法契约（`electron/radar/types.ts:42`）+ 在两处注册（`collectors/registry.ts` 工厂表、`radar-config.ts:27` 的 `ALL_TOOLS`）**。接入后自动获得两条通道：3 秒一次的轻探针（只读元数据，产出 running/idle 状态跃迁）和 60 秒一轮的指纹增量采集（解析正文入库）。当前已接入 **9 个智能体**：zcode / claude-code / codex / opencode / qoder / trae / dsh / pi / mcode。
>
> **2026-11-24 更新**：AutoClaw（tool=autoclaw）已按第六节流程接入，现为 10 个；实现与冒烟验证记录见 [docs/更新日志.md](<docs/更新日志.md>) 未发布区。

## 二、总体架构：探针在哪跑、怎么接上智能体

```
~/.zcode  ~/.claude  ~/.codex  opencode.db  qoder  Trae  ~/.dsh  ~/.pi  ~/.minimax   ← 各智能体的本地数据（只读）
        │
        ▼ 每个工具一个 collector（HubCollector 实现）
┌─ worker 线程（agent-radar.ts:88 创建，唯一写端）─────────────────────────┐
│  RadarMonitorLoop  每 3s 逐 collector 跑 probe()  → running/idle 跃迁      │
│        │ 有新写入 → onDirty(tool)（单向提速，不阻塞探针）                  │
│  RadarIngestLoop   15s 首轮 + 60s 定轮（dirty 可提前触发）                 │
│        │ listAll → 元数据 upsert → 指纹变更的会话按 seq 增量写            │
│  radar.db（正本）+ fingerprints.sqlite（游标）+ status.json               │
└──────────────────────────────────────────────────────────────────────┘
        │ postMessage {state|round|ready}
        ▼
主进程（只持 radar.db 只读连接做 UI 查询，agent-radar.ts:312-327）
        │ sendToRenderer('radar:event', …)   main.ts:2160
        ▼
渲染层（preload 白名单含 'radar:event'，preload.ts:8）→ 雷达页/徽标/问雷达
```

要点：

| 事实 | 依据 |
|---|---|
| 全部采集内核（collectors+monitor+ingest+写端）跑在**一个 worker 线程**，重 IO/CPU（整文件解析、zstd 解压、SQLCipher 解密、批量入库）不堵主进程 | agent-radar.ts:88、头注释 :1-13 |
| 主进程**只读**查询；写操作经 postMessage 转回 worker | agent-radar.ts:312-327、:193-211 |
| 监控与同步两通道独立起搏，唯一交点是 `onDirty` 单向通知：探针在 activeWindow（3 分钟）内见到源库新写入才触发，ingest 侧四重防抖（引擎未启/在跑忽略 → 跑完 15s 内节流 → dirty 定时器合并 → 再延 2s），最快每 15s 提前一轮且永不阻塞探针 | radar-monitor.ts:172-176、radar-ingest.ts:77-86 |
| 状态跃迁三处理：`running===false` 立即归位；`running===true` 直接信任（collector 保证僵死翻转，监控侧另加 45 分钟保险 `EXACT_BACKSTOP_MS`）；无精确信号按 3 分钟活跃窗推断 | radar-monitor.ts:109-147、:25 |
| 启动自愈：清扫上次残留的僵尸 running → 预置已有 running（重启不重复发事件）；worker 意外退出按指数退避 5s→60s 自动重启 | radar-monitor.ts:55-70、agent-radar.ts:125-141 |
| 数据全部本地 `~/.qihang-ai-desktop/radar/`，不出机器；功能默认关（`agentRadarEnabled` 默认 `'0'`），设置页显式开启 | radar-config.ts:30-33、main.ts:2159 |

### 配置全景（agent-radar.ts:31-45 `buildConfig`）

| config.json 键 | 默认 | 语义 |
|---|---|---|
| `agentRadarEnabled` | `'0'` | 总开关，默认关 |
| `agentRadarIntervalMs` | 60000 | 同步轮间隔（对话入库通道） |
| `agentRadarMonitorMs` | 3000 | 探针间隔（实时监控通道） |
| `agentRadarExclude` | `''` | 排除项目目录（逗号/分号/换行分隔，子目录递归；**只过滤采集，不过滤探针状态监控**） |
| `agentRadarTools` | 空=全开 | 启用的工具清单，**只认 ALL_TOOLS 内的值**（agent-radar.ts:32-34 白名单过滤） |

另有三个可调参数：`autoFreezeDays`（30 天无动静自动冻结）、`activeWindowMs`、`idleTimeoutMs`（agent-radar.ts:40-44）——2026-11-24 起可经 `agentRadarAutoFreezeDays` / `agentRadarActiveWindowMs` / `agentRadarIdleTimeoutMs` 配置（默认 30 天 / 3 分钟 / 3 分钟，0 天 = 关闭自动冻结），设置页可改。

## 三、接入契约：`HubCollector`（types.ts:33-45）

```ts
export interface HubCollector {
  readonly tool: string;                                  // 工具键名（= ALL_TOOLS 之一）
  listAll(): Promise<SessionInfo[]>;                      // 全量列举会话元数据
  loadMessages(s: SessionInfo): Promise<SerializedMessage[]>;  // 拉取正文（同步轮才调）
  probe(): Promise<Map<string, ProbeSignal>>;             // 轻探针（监控轮每 3s 调）
  dispose(): Promise<void>;
}
```

三条**契约语义**（接口注释明文规定，是接入设计的硬约束）：

1. **probe 只读元数据（mtime/回合状态等），绝不解析消息正文** —— 这是实时通道"毫秒级、每 3s 一次"的成本保障，消息解析全部留给同步轮（types.ts:37-40 注释）。
2. **实报 `running=true` 的 collector 必须保证僵死回合（崩溃没写结束状态）在有限时间内翻转为 false**（types.ts:31-35）——监控侧 45 分钟兜底只是保险，collector 自己要有更短的翻转窗口。
3. `ProbeSignal = { ts: 源库最近写入毫秒, running?: true|false|缺省 }` —— 缺省 `running` 时监控层退回"3 分钟活跃窗内=运行、超时归位"的时间窗推断（radar-monitor.ts:139-147）。

配套数据结构：`SessionInfo { id, label?, file, messageCount, createdAt, updatedAt?, projectDir?, archived? }`（`updatedAt` 是增量检测依据）；`SerializedMessage { role, content, thinking?, tools?[{name,args?,result?,status?}], timestamp }`。

容错边界（引擎已兜住，接入方无需自建）：单个 collector 构造失败不影响其余工具（registry.ts:31-34）；`probe()`/`listAll()` 抛错被 monitor/ingest 捕获跳过该工具本轮（radar-monitor.ts:98-101）。

## 四、9 个智能体的探针接入现状

### 4.1 总对照矩阵

| | 数据源（本机） | 探针稳态成本 | 窗口 | running 判定 | 僵死兜底 |
|---|---|---|---|---|---|
| **zcode** | `~/.zcode/cli/db/db.sqlite`（常驻只读连接） | 1 条 SQL（+模糊态 1 次 EXISTS） | 30min | **精确**：`turn_usage` 回合状态机 + `hasRunningPart` | 硬运行 30min + 模糊态 90s（+监控 45min） |
| **claude-code** | `~/.claude/projects/<编码目录>/*.jsonl` | 纯 stat | 10min | 时间窗推断 | —（不报 running） |
| **codex** | `~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl`（深度 3 walk） | 纯 stat；新文件首见读 1MB 头 | 10min | 时间窗推断 | — |
| **opencode** | `~/.local/share/opencode/opencode.db` | 1 条 SQL（每轮新开/关连接） | 10min | 时间窗推断 | — |
| **qoder** | `%APPDATA%`（mac 为 `~/Library/Application Support`）/`com.qoder[cn].app.stable/main.sqlite` | 1 条 JOIN 聚合 SQL | 10min | 时间窗推断 | — |
| **trae** | `%APPDATA%`(mac 同上)/`Trae CN\|Trae/ModularData/ai-agent/database.db`（SQLCipher 加密） | 源库四元组未变：2 次 stat + 小 SQL | 10min | 时间窗推断 | — |
| **dsh** | `~/.dsh/sessions/<cwd-slug>/<会话目录>/session.v{4,3}.jsonl.zstd` | 每文件 1 次 stat | 10min | **精确**：日志尾部回扫 `turn/start` vs `turn/end` | 崩溃回合由监控侧 45min 兜底 |
| **pi** | `~/.pi/agent/sessions/<编码目录>/*.jsonl` | 目录遍历 + 每文件 1 次 stat | 10min | 时间窗推断 | — |
| **mcode** | `~/.minimax/v2/sqlite/runtime-state.sqlite`（元数据）+ `~/.minimax/v2/sessions/<history_relative_dir>/messages.jsonl`（正文） | 1 条 SQL 全表 | 兜底路径 10min | **精确**：`status==='started'` | collector 20min（`RUNNING_STALE_MS`，mcode.ts:43）+监控 45min |

**规律**：有"回合状态机"可读的工具（zcode `turn_usage`、dsh `turn/start|end`、mcode `status`）报精确 running，秒级跃迁；只有文件流可看的（claude-code/codex/opencode/qoder/trae/pi）退回时间窗推断。这是接入新工具时的第一个设计决策：**优先找源工具自己的回合信号，其次才用 mtime 窗口**。

### 4.2 各接入方式分型

按"元数据与正文从哪来"，9 个采集器分四型：

**① SQLite 单源**（zcode / opencode / qoder）
- 元数据与正文同库不同表。zcode：`session`/`message`/`part` 三层，part 经 `message_id` 天然挂靠、state 内联 input/output，**无需配对启发式**（zcode.ts:72-142）；user 消息剥 `visibility='model-only'` 噪声。
- opencode：**schema 容错范本**——会话表双候选 `session_v2` 优先、`session` 其次（:35-39），正文按 `message+part`（v1）/`session_message`（v2）两代解析器路由（:169-184），绝不让一个工具的 schema 变化打挂采集。
- qoder：**增量信号修复范本**——其会话行 `updated_at` 只在用户提问时更新，AI 回复采不进；listAll/probe 都改取 `MAX(会话.updated_at, 消息行最大 updated_at)`（qoder.ts:55-59、148-152），回合一结束即可被探针发现。

**② JSONL 文件流**（claude-code / codex / pi）
- 元数据 = stat + 头部探针（claude-code 256KB、codex 1MB、pi 128KB），mtime+size 双键缓存；`messageCount` 可恒 0（不数消息，增量靠 mtime）。codex 的 `session_meta` 首行混着巨型 base_instructions，只能正则提取不能整行 JSON.parse（codex.ts:104-123）。
- claude-code 的工具结果不回填（结果以 user 行出现在时间线）；codex 做 `call_id` 配对 + 乱序回溯 + 回合分组（assistant 文本/reasoning/function_call 聚成一条）；pi 的 toolCall 块自带 result 无需配对。
- pi **排除自身**：`assistant-v2-` 前缀是启航工作台自己的会话文件，不重复采集（pi.ts:19、32）。

**③ 加密/压缩日志**（trae / dsh）
- trae：SQLCipher 4 页级 AES-256-CBC 解密（密钥逆向自 ai_agent.dll，trae-db-worker.ts:20），整库解到系统临时目录的明文缓存库，**叠加 WAL 明文帧**（未 checkpoint 的最新写入也能看到，:68-109）；源库 mtime/size + WAL mtime/size 四元组未变则探针只花 2 次 stat（:251-254）；重解有 8s 节流、缓存带实例+时间戳后缀绝不覆盖别人正打开的文件。解密 worker **必须打包到 asar 外**（Node worker 线程读 asar 内文件不可靠；package.json:125 已把整个 radar 编译目录 asarUnpack）。
- dsh：**多帧 zstd 是核心坑**——Node 内置 zlib 只解第一帧，统一走 `@mongodb-js/zstd`（可选原生加速）+ `fzstd` 纯 JS 兜底（dsh.ts:15-28）。元数据全部来自日志事件本身；running 靠日志尾部回扫 `turn/start|turn/end` 谁在后谁是权威（:102-109）。

**④ SQLite 元数据 + JSONL 正文双源**（mcode，最新接入的先例）
- 元数据取 `local_runtime_sessions`（title/status/project_workspace_dir/history_relative_dir），正文取 `messages.jsonl`（与 pi 同构，多 `compactionSummary`/`custom` 两种 role）；库不可用逐级降级到 manifest 文件层（mcode.ts:120-231）。
- **噪声剥离是必须项**：mcode 把运行时提示塞进 user 消息，实测占 user 文本 79.7%；用 11 个已知标签白名单成对剥除（`NOISE_TAGS`，mcode.ts:51-65），**不做通用 XML 正则**——用户正文里可能合法包含 `<svg>` 等标签。
- 工具结果按 `toolCallId` 跨行配对，收尾把没等到结果的 `running` 统一翻 `done`（:301-337）。
- 完整接入过程见先例文档 [docs/雷达接入MiniMax方案.md](<docs/雷达接入MiniMax方案.md>)。

## 五、探针之外：采集如何落地（指纹增量 + 本地正本库）

探针只回答"谁在动"；正文采集由同步通道完成，接入方只需保证 `updatedAt` 真实、`loadMessages` 幂等可重放：

- **指纹** `Fingerprint { sourceUpdatedAt, messageCount, lastSyncedSeq }`（fingerprint-store.ts:12-16），存 `fingerprints.sqlite`；语义是**同步游标而非聊天数据**，删掉后凭本地库 `last_synced_seq` 续传或全量重建。
- **增量决策**（radar-ingest.ts:239-257）：无指纹 → full；消息条数增长超过 `max(指纹条数, 本地 lastSyncedSeq)` → delta（只取 `seq > fromSeq`）；源缩水 → full 重采覆盖。
- **seq 幂等写入**：`radar_message` PK `(tool, session_id, seq)`，upsert `ON CONFLICT DO UPDATE`——重复写等价覆盖；`seq` 先按解析序号编号、后过滤空消息（存在空位，delta 靠它对齐）。**写库事务提交成功后才前进指纹**，中途崩溃最多重写一遍幂等数据（radar-ingest.ts:273、radar-db.ts:199-238）。
- **正本库**：`radar_session` / `radar_message` / `radar_state_event` / `radar_message_fts`（FTS5 trigram，中文三字全文检索）；冻结只停采集、检索与摘要照常（radar-db.ts:421-438）。
- **截断**：正文/思考单条 200KB、工具字段 2KB（radar-ingest.ts:15-16）。

## 六、接入一个新智能体的标准流程

### 6.1 必改清单（引擎侧三步，缺一不可）

| # | 文件 | 改动 |
|---|---|---|
| 1 | `electron/radar/collectors/<tool>.ts` | **新增**，实现 `HubCollector`（参照体量：opencode 207 行 / pi 216 行 / mcode ~400 行） |
| 2 | `collectors/registry.ts:16-27` | import + `factories` 工厂表加一项（顺序即遍历顺序；单个构造失败已由引擎兜底） |
| 3 | `radar-config.ts:27` | `ALL_TOOLS` 加新 tool id——否则 `agentRadarTools` 白名单过滤会把它丢掉（agent-radar.ts:32-34），空配置回退也不会启用它（registry.ts:15） |

数据库无枚举约束（`tool` 是自由 TEXT），引擎侧 ingest/monitor/指纹/落库/UI `allTools` 透出全部自动生效。

### 6.2 可选改动

- 前端 4 个视图的工具标签：`src/views/{AgentRadarView,RadarAskView,RadarAllView,RadarSummaryView}.vue`；
- `src/views/ConfigView.vue`（采集工具多选）、`HelpView.vue`（帮助文案）；
- `config.json` 的 `agentRadarTools`（**留空 = 全开**，通常无需改）。

### 6.3 设计要求（从契约与 9 个先例的踩坑提炼）

1. **先找源工具自己的回合信号**（状态机/回合事件），有就报精确 running 并配僵死兜底（建议 ≤30min 翻转 false）；没有就只报 `{ts}` 走时间窗推断，不要硬造 running。
2. **`updatedAt` 必须真实反映"有新写入"**——qoder 教训：会话行不更新而消息行更新时，必须取两者 MAX，否则指纹永远不变、AI 回复采不进。
3. **probe 毫秒级**：SQLite 用单条元数据 SQL；文件系用 stat + mtime 窗口（惯例 10min，长静默工具可放宽如 zcode 30min）；头部探针必须有 mtime+size 缓存。
4. **schema 容错**：表/列存在性判断，缺失即跳过或降级（opencode/mcode 范式）；外部库不存在返回空列表（工具未安装 ≠ 错误）。
5. **只读打开 WAL 库**统一走 `openSqliteReadonly`（sqlite-open.ts:9-17：readOnly 失败退回普通打开让 SQLite 完成 WAL 恢复）。
6. **噪声剥离用已知标签白名单**，绝不用通用 XML 正则；系统提示注入不剥会污染问雷达检索、让简报复读提示词。
7. **时间戳统一毫秒**（trae 是秒要 ×1000）；`file` 字段定位源存储（sqlite 会话 id 或 jsonl 绝对路径）；加密/压缩源把重活放独立 worker 且打包到 asar 外。
8. **工具调用结果的配对方式**按源格式选：内联 state 无需配对（zcode/opencode/qoder/pi）、`call_id` 配对（codex/dsh）、跨行 `toolCallId` 配对（mcode）；收尾把未回填的 `running` 翻 `done`。

## 七、反向链路：雷达数据如何回流给智能体

"接入当前智能体"的另一面——雷达沉淀的数据被本工作台的 AI 消费：

- **问雷达**：`radar:ask` IPC → `radar-ask.ts:194` → `generateWithPi` → pi SDK（in-process），本地检索片段（FTS trigram + 会话级兜底）作答、带来源标注；前端可选模型（`RadarAskView.vue`）。
- **会话摘要（提炼层②）**：worker 订阅 idle 收口事件 → 价值分门槛（`MIN_SCORE=3`、`MIN_NEW_MSGS=4`、收口后延迟 20s 等尾消息）→ 达标才调模型；高价值摘要落盘笔记库 `AI活动/会话/*.md`（radar-digest.ts:34-42、radar-note-save.ts）。
- **昨日简报**：radar-brief 多 agent 分片生成，今日待办五道闸挑选。
- 三处 AI 调用全部经 pi SDK，模型运行时读 `~/.pi/agent/models.json` + `auth.json`——换模型（如 MiniMax）是零代码配置项，详见 [雷达接入MiniMax方案.md](<docs/雷达接入MiniMax方案.md>) 第三、五节。
