# 启航AI工作台（Qihang AI Desktop）

> 一个**围绕本地项目库工作的个人 AI 智能体**：对话即查、任务即执行、数据即分析，你的 Markdown 笔记目录是数据主体。**开箱免费用，数据留本地，手机上指挥。**

## 定位：围绕本地项目库的个人 AI 智能体

**项目就是本地目录**：每个「项目」指向你磁盘上的一个文件夹（笔记库 / 代码库 / 资料库都行），AI 对话按所选项目目录运行，直接读取、写入目录里的 Markdown 文件作答；综合日报聚合所有项目；飞书派活、任务结果存档默认写入默认项目。

| 支柱 | 一句话 | 对应功能 |
|------|--------|----------|
| 📁 **主体：本地项目库** | Markdown 目录即数据主体，AI 直接读写 | 项目库 / 笔记 / 今天页 |
| 🧠 **智能面：助理 + 数据分析** | 对话、待办、提醒 + MCP 数据源分析、日报报告 | 对话 / 任务 / 数据源 / 技能 |
| 📶 **触达面：飞书** | 移动指挥与推送回路，可断开不影响主功能 | 飞书 Bot / 日报 |

> 触达面是场景包，不是前提：断开一切外部连接，工作台依然完整可用。

## ✨ 核心卖点

**1. 项目库为中心的自动化链路**

```
笔记 → 分析 → 建议 → 执行 → 推送 → 回到笔记
```

1. **笔记**：Markdown 随手记，各项目目录即数据主体；外部系统数据经 MCP 数据源接入。
2. **分析**：AI 直接读项目文件回答提问、查 MCP 数据源里的业务数据，而不是凭空瞎编。
3. **建议**：AI 不只回答问题，还给出可执行建议——该做的事、该记的档。
4. **执行**：对话落成定时/循环任务，AI 用原生 `read`/`bash`/`write` 直接操作项目文件。
5. **推送**：定时提醒、每日 AI 日报，通过飞书推送到你的群和联系人；结果最终都归档回项目库。

**2. 深项目库架构**：项目库的检索与读写交给 AI agent 自己完成——工作台不再维护笔记工具层和向量索引，AI 用自带的 `read`/`bash`/`write` 按 `AGENTS.md` 约定直接操作项目目录；概览统计走实时扫盘，项目库里有什么，数字就是什么。

**3. 本地优先**：对话记录全部留在本机 SQLite，项目库就是你磁盘上的文件夹，随时可用任何编辑器打开、随时带走。

**4. 单引擎架构**：pi 引擎（`@earendil-works/pi-coding-agent`）直接运行在主进程内，对话、飞书、任务、日报、技能共用一条链路；本地工具以 customTools 原生注入，无子进程、无需安装 CLI。

**5. 手机指挥**：飞书 Bot 一等入口——卡片选项目、接着问续聊、收日报。笔记本合盖在外面，手机照样指挥。

**6. 全新 UI**：固定侧边栏一天视角——「今天」总览、对话、任务、待办、笔记、数据一键直达；明暗主题切换；任意页面一键新开对话草稿；侧栏实时显示引擎与飞书服务状态。

| ✅ **待办与提醒** | 每日/每周/每月/每年/一次性提醒，系统通知 + 飞书推送；与笔记提炼看板联动 |

| 🔗 **飞书集成** | Webhook 推送群通知；Bot 长连接在飞书里直接对话；**卡片交互**——每条消息先弹项目选择卡片，结果卡片支持「💬 接着问」续聊与跨项目重跑 |
| 📰 **自动日报** | 每天定时汇总所有项目笔记、任务、对话，生成 AI 日报并推送（支持自定义提示词与模板） |
| 🤖 **pi 引擎** | SDK 内置主进程（模型注册/会话/流式输出/本地工具注入），无需安装 CLI；对话、飞书、定时任务、技能共用同一工具面 |

## 快速开始

1. **安装启动**：双击安装包（pi 内核已内置，无需安装 Node 或任何 CLI）。
2. **设置项目**：「设置 → 📁 项目」，添加你的 Markdown 文件夹并设为默认——这是你的数据主体，之后所有对话、任务、日报都围绕它展开。
3. **配置模型**：「设置 → 💬 对话模型配置」，选「默认（DeepSeek）」只填 API Key，或「自定义」接任意 OpenAI 兼容接口。
4. **开始使用**：在「对话」页提问（AI 会直接读你的项目文件作答），「今天」页看待办与日报，「任务」页建定时任务，「数据源」页接入外部 MCP 数据源（可选）。
5. **连接手机（可选）**：配置飞书 Bot，在手机上下发任务、收日报、继续对话。

## 飞书使用指南

> 📖 **飞书没配过、不知道从哪开始？** 请看 [docs/飞书连接指南.md](docs/飞书连接指南.md)：两种接入方式的完整开通步骤、所需权限清单、卡片回调订阅与常见问题排查，一篇讲清。

### 1. Webhook 推送

粘贴飞书群机器人 Webhook 地址，AI 日报、提醒即可推送到群。

### 2. Bot 对话

在飞书开放平台创建应用，填 `App ID` / `App Secret`，启动后可在飞书私聊/群聊中直接使用 AI。

### 3. 卡片交互

- **项目选择卡片**：多项目时每条消息先弹「请选择项目」卡片，点按钮即指派；也可用 `/项目 名称`、`/项目 序号`、直接回复序号、消息开头写项目名或行内标记 `[笔记库：X]` 指定。
- **结果卡片**：执行结果标注「本条发到：X」，点「💬 接着问」可在飞书里继续该话题（同一会话续聊 30 分钟窗口），不点则每条消息都是新话题。
- **前置条件**：需在飞书开放平台为应用订阅「卡片回调」（`card.action.trigger`）事件；未订阅时按钮不可用，回复序号/指令仍然有效。

## 手机访问与内网穿透（frp）

出差不带电脑也能用：手机浏览器直接访问家里电脑上的工作台，对话、选项目、看历史都走 App 自带的本机网关。公网入口通过 [frp](https://github.com/fatedier/frp) 打通，**服务端装在云服务器，客户端由 App 托管**。

### 链路

```text
手机浏览器
   │  http(s)://<公网IP或域名>:18791
   ▼
frps（云服务器，常驻）
   ▲  出站长连接（7000）
   │
frpc（家里电脑，由 App 启动和守护）
   │
工作台本机网关 127.0.0.1:8791
```

- App 网关只监听 `127.0.0.1:8791`，不直接暴露到公网
- frpc 随 App 自启、异常退出自动重连（3s 起、最长 60s 退避），关闭 App 即断开
- 手机首次访问需输入配对码（6 位、5 分钟有效、一次性），换取该设备的随机 token

### 一、下载安装 frp

1. 打开 <https://github.com/fatedier/frp/releases>，下载对应平台的发行包（以 `frp_0.72.0` 为例）
   - Windows（家里电脑）：`frp_0.72.0_windows_amd64.zip`
   - Linux（云服务器）：`frp_0.72.0_linux_amd64.tar.gz`
2. 解压后只需要 `frpc`/`frpc.exe`、`frps`/`frps.exe` 和各自的 `*.toml` 配置文件，其余可删。

### 二、服务端 frps（云服务器）

1. 把 `frps` 与 `frps.toml` 上传到服务器，例如 `/opt/frp/`
2. `frps.toml` 示例：

```toml
bindPort = 7000
# 鉴权 token，客户端必须一致，请改成你自己的强随机串
auth.token = "YOUR_STRONG_TOKEN"

# 可选：管理面板（建议只绑 127.0.0.1，通过 SSH 隧道查看）
webServer.addr = "127.0.0.1"
webServer.port = 7500
```

3. 放行端口：云厂商安全组和系统防火墙都要放行 `7000`（frps 控制端口）和 `18791`（对外映射端口）
4. 启动：
   - Linux：`chmod +x frps && ./frps -c frps.toml`
   - Windows：`frps.exe -c frps.toml`
5. 常驻用 systemd（可选）：

```ini
[Unit]
Description=frps
After=network.target

[Service]
Type=simple
ExecStart=/opt/frp/frps -c /opt/frp/frps.toml
Restart=always

[Install]
WantedBy=multi-user.target
```

```bash
systemctl enable --now frps
```

### 三、客户端 frpc（运行工作台的电脑）

`frpc.toml` 示例，端口与工作台默认网关一致：

```toml
serverAddr = "你的云服务器IP"
serverPort = 7000
auth.token = "YOUR_STRONG_TOKEN"

[[proxies]]
name = "qihang-mobile"
type = "tcp"
localIP = "127.0.0.1"
localPort = 8791
remotePort = 18791
```

### 四、在 App 内开启（推荐，不用手动跑 frpc）

1. 「设置 → 📱 移动端」打开「启用移动端网关」，端口保持 `8791`
2. 在「🔗 frpc 内网穿透」中：
   - **frpc 程序路径**：选择 `frpc.exe` 实际位置
   - **frpc 配置文件**：选择上面的 `frpc.toml`
   - 勾选「随 App 启动 frpc」，点「应用 / 重启」
3. 状态区显示「运行中 + PID」即成功；App 退出时会一并关闭 frpc
4. 点「生成配对码」，手机打开 `http://<公网IP>:18791/`，输入 6 位配对码绑定

之后每次启动 App，网关和 frpc 都会自动拉起，无需再手动运行或保留终端脚本。

### 五、安全建议

- `frpc.toml` 属于本机私密配置，不要提交到仓库（本文档中的 token 一律为占位符）
- 公网 `18791` 适合联调期；长期方案建议域名 + HTTPS（nginx 反代到 18791），随后关闭公网端口
- 手机丢失或更换：清空 `~/.qihang-ai-desktop/mobile-devices.json` 可撤销全部配对设备，再重新生成配对码

### 六、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 设置页 frpc 显示未运行 | 程序或配置文件路径不存在 | 检查两个路径是否存在，查看日志中的 `[Frpc]` 行 |
| 日志 `token in login doesn't match` | 客户端与服务端 token 不一致 | 两端 `auth.token` 保持一致后重启 |
| 日志 `port already used` | `remotePort` 被其他进程占用 | 改 `remotePort`，或停掉占用进程 |
| 手机打不开页面 | 端口未放行或 frpc 未连上 | 先测 `http://IP:18791/api/health`，再查安全组/防火墙 |
| frpc 反复重启 | 网络抖动或地址错误 | App 会自动退避重连；持续失败看设置页 `lastError` |

## 配置指南

### 1. AI 模型

- **默认（DeepSeek）**：只需填 API Key 即可快速开始
- **自定义**：任意 OpenAI 兼容接口（DeepSeek、Ollama、LM Studio 等），填 Base URL / API Key / 模型名，可配多个 Provider、多个模型，对话页随时切换

### 2. 网络搜索

- **自动引擎（默认）**：免费可用，百度 / Bing / DuckDuckGo 自动降级
- **增强（可选）**：配置博查或 Serper 的 API Key，更稳定、中文效果更好

### 3. 飞书

- 飞书 Webhook（群推送）与飞书 Bot（应用凭据）互相独立，可任选或同时开启
- 卡片按钮需在飞书开放平台订阅「卡片回调」事件

### 4. 任务与日报

- 「任务」页创建任务，支持立即、指定时间或定时循环触发，结果保存到项目库，可选推送飞书
- 「设置 → 📊 综合日报设置 / 🤖 日报 AI 提示词」管理每日日报的保留天数、生成提示词与输出模板

### 5. 数据备份

- 「设置 → 💾 数据备份与恢复」一键备份、开启每日自动备份（保留最近 N 份）、从备份文件一键恢复（恢复后重启应用生效）

## 数据与隐私

- 所有数据保存在本机：SQLite 数据库（`~/.qihang-ai-desktop/qihang-ai-desktop.db`）与你的项目文件夹。
- 对话内容默认会发送给你所配置的模型服务商用于生成回复。
- 如需**完全离线**：对话模型配置为 Ollama 本地模型即可（此时除软件自动更新外无任何网络请求）。
- 飞书凭据等敏感配置保存在本机 `config.json`（已加入 `.gitignore`，不会进入仓库）。

## 常见问题（FAQ）

**Q：首次对话提示需要配置模型？**
A：在「设置 → 💬 对话模型配置」填 API Key（默认 DeepSeek）或自定义 OpenAI 兼容接口，点「测试」验证。

**Q：AI 答非所问，没有用到我的笔记？**
A：检查「设置 → 📁 项目」是否已添加并选中目标项目；对话页顶部可切换会话所属项目。

**Q：飞书卡片按钮点了没反应？**
A：需在飞书开放平台为应用订阅「卡片回调」（`card.action.trigger`）事件并重新发布版本；未订阅时直接回复序号或 `/项目 N` 同样有效。完整排查见 [docs/飞书连接指南.md](docs/飞书连接指南.md)。

**Q：飞书里怎么接着上一个话题聊？**
A：点击结果卡片上的「💬 接着问」进入续聊模式，之后直接回复即可；发 `/` 开头命令或点项目选择按钮则退出续聊开始新话题。

**Q：可以完全离线使用吗？**
A：可以。对话模型配置为 Ollama 本地模型即可，不开启飞书/联网搜索就没有任何外部依赖。

**Q：数据会丢失吗？**
A：数据保存在本机数据库，正常退出不丢失。可在「设置 → 数据备份与恢复」一键备份、开启每日自动备份（保留最近 N 份），或从备份文件一键恢复（恢复后重启应用生效）。

## 开发者指南

### 环境要求

- Node.js 22.19+（pi agent SDK 的硬性要求；Electron 39 内置 Node 22.22，开发用的命令行 Node 建议同版本）
- Electron 39（应用内已固定，**不要单独升级/降级**；升级后必须 `npx electron-rebuild -f -w better-sqlite3` 重编原生模块）
- 可选：Ollama（本地对话模型）

### 开发调试

```bash
npm install            # 安装依赖（含 Electron 原生模块编译）
npm run dev            # 编译主进程 + 启动 Vite 开发服务器 + 启动 Electron
npm run dev:web        # 仅启动 Vite 前端（纯浏览器预览，带示例数据垫片，不开 Electron）
```

### 测试

```bash
npm run test:router    # 飞书多项目路由单元测试（103 条断言）
```

### 构建

```bash
npm run build            # vite build + tsc 编译 + electron-builder 完整打包
npm run build:web        # 仅构建前端产物（不打包安装程序）
```
